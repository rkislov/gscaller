# gscaller

Автор: **Кислов Роман Сергеевич** · [Apache 2.0](LICENSE)

Небольшой монитор трафика для строки меню macOS. Расчёты и сохранение — Go, интерфейс — AppKit через небольшой мост Objective-C. Внешних зависимостей, сетевых запросов приложения и телеметрии нет.

## Установка

Скачайте `gscaller-0.1.0-macos-arm64.zip` из [GitHub Releases](https://github.com/rkislov/gscaller/releases), распакуйте и перенесите `gscaller.app` в `/Applications`. Этот релиз собран для Apple Silicon.

Приложение имеет локальную ad-hoc подпись, без Developer ID и notarization. macOS может запросить разрешение на открытие приложения, скачанного из интернета. Используйте штатное подтверждение в настройках конфиденциальности и безопасности macOS.

## Сборка из исходников

Требуются macOS 12+, Go 1.24+ и Xcode Command Line Tools (`xcode-select --install`). Сборка предназначена для архитектуры текущего Mac; здесь проверена Apple Silicon.

```sh
make build
open build/gscaller.app
```

Готовое приложение находится в `build/gscaller.app`. Можно перенести его в `/Applications`. Оно работает без окна и значка Dock. Для выхода нажмите на показатели в строке меню и выберите «Завершить gscaller».

В строке меню две компактные строки: загрузка сверху, отдача снизу. Обычный моноширинный шрифт и отдельные колонки выравнивают стрелки, числа и единицы. По умолчанию показана скорость; пункт «Показывать скорость в строке меню» переключает её на объём за день. Короткие единицы KB/s и MB/s используют множитель 1024; точные обозначения КиБ/с и МиБ/с доступны в меню. Меню содержит объём за день, за сеанс и за всё время наблюдения. Интервал 2, 5, 10 или 30 секунд запоминается. Автозапуск при желании можно добавить в настройках macOS, в разделе объектов входа.

## Энергопотребление

- По умолчанию системный снимок счётчиков и проверка маршрутов IPv4/IPv6 раз в 5 секунд, без запуска `netstat` и других процессов.
- Нативный `NSTimer` с допуском 25% позволяет системе объединять пробуждения. Фактическое время между замерами используется для вычисления скорости.
- В режиме энергосбережения интервал составляет минимум 10 секунд.
- При выключенном экране и во время сна таймер остановлен. После пробуждения объём учитывается по разнице счётчиков, а скорость начинает измеряться заново.
- Файл статистики обновляется не чаще раза в минуту при изменении данных, а также перед сном и штатным выходом.
- Текст показателей обновляется только при изменении. Нет анимаций, веб-интерфейса и частого опроса процессов.

Go runtime и AppKit также используют память и процессорное время. Для контрольного замера есть `tools/process_probe.c`: он читает счётчики CPU, памяти, пробуждений и энергии процесса через `proc_pid_rusage`. Поле `ri_energy_nj` — оценка энергии, которую ядро относит к процессу; это не прямой замер батареи и не полная стоимость с учётом WindowServer и других системных служб. Если macOS не возвращает это поле или оно не изменяется, нулевую дельту нельзя трактовать как нулевой расход энергии. Для `powermetrics` требуются права администратора.

Для собственного сравнения запустите мониторы по очереди при одинаковой нагрузке и интервале обновления. В «Мониторинге системы» сравните CPU и «Воздействие на энергопотребление» за достаточно длительный период. Для минимальной частоты пробуждений выберите 30 секунд.

## Как считается трафик

Читаются 64-битные счётчики `sysctl NET_RT_IFLIST2`. Автовыбор проверяет маршруты IPv4/IPv6 через системный routing socket. Если маршрут по умолчанию проходит через `utun*`, `ppp*` или `ipsec*`, учитывается выбранный туннель, а физические интерфейсы исключаются, чтобы не суммировать исходные и зашифрованные данные. При отсутствии VPN учитываются `en*` (Wi-Fi, Ethernet и USB-адаптеры). Переключение сети устанавливает новый исходный снимок, без добавления исторических байтов.

При активном VPN прямой трафик, который обходит выбранный туннель, в текущем режиме не учитывается. Без VPN учитываются также локальная сеть и служебный трафик физических интерфейсов. Loopback, мосты и AWDL исключены. Это не точный счётчик интернет-тарифа провайдера. Суммирование нескольких физических подключений также может учитывать пересылаемый между ними трафик дважды.

Первый снимок после запуска устанавливает исходные значения: трафик до запуска приложения не импортируется. Сброс счётчика, новый интерфейс и изменение его индекса не вызывают скачков. Во время остановленного приложения и после ошибки чтения часть трафика может быть не учтена. При аварийном завершении могут потеряться изменения после последнего сохранения.

Граница дня определяется локальным временем Mac. Весь прирост между двумя замерами относится ко дню последнего замера; если сон пересёк полночь, разделить этот прирост между днями невозможно. На первом обновлении после полуночи дневной счётчик обнуляется.

Статистика: `~/Library/Application Support/Scaler/usage.json`, атомарная замена файла с правами `0600`. При повреждении файла приложение показывает ошибку и не перезаписывает его. Параметры интерфейса хранятся в стандартных настройках приложения `local.gscaller.app`.

## Проверка

```sh
make test
build/gscaller.app/Contents/MacOS/gscaller --sample
```

Тесты проверяют разницы счётчиков, сброс, отключение и появление интерфейсов, пробуждение, смену дня, сохранение и чтение реального системного снимка. `make test` также запускает race detector и `go vet`.

Сборка подписана локальной ad-hoc подписью. Developer ID, notarization и проверка на Intel Mac в эту версию не входят.


Для воспроизводимой проверки на текущем Mac:

```sh
clang -Wall -Wextra -Werror -O2 tools/process_probe.c -o build/process_probe
build/process_probe "$(pgrep -x gscaller)" 60 5
```

Для проверки выбранного интерфейса используйте `--sample`. Опциональный флаг `--diagnostics /absolute/path/trace.jsonl` записывает контрольные снимки, рассчитанные скорости, фактический текст кнопки и её ширину в пунктах. В обычном запуске эти записи отключены. `tools/verify_runtime.py` сравнивает два запущенных процесса, пишет независимые снимки `netstat` и скачивает 8 МиБ / отправляет 1 МиБ нулевых тестовых данных в speed.cloudflare.com. Проверка создаёт дополнительную нагрузку; её следует запускать отдельно от обычного использования. Опциональный PID второго монитора передаётся флагом `--reference-pid`; без него измеряется только gscaller.
